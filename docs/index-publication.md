# 一致索引发布与恢复（任务 4.1–4.4）

第 3 批准备的 SQLite 候选现在由 `IndexCoordinator` 发布。正常 worker 和 CLI 默认完成准备、校验及发布后才返回 `ready=true`。这表示语义与关键词检索资源完整，不代表已通过真实模型/生成 API 的问答质量验收。

## 资源身份与目录

- 原文件遵守 `PDF_STORAGE_PATH`；向量遵守 `CHROMA_PERSIST_DIRECTORY`；关键词/映射快照保存在 `PROCESSED_DATA_PATH/indexes/`。
- Chroma 集合使用完整 embedding 指纹和独立版本 UUID。集合元数据保存完整模型/revision/tokenizer/处理策略 profile、cosine 距离和文档库身份；每个片段保存整数文档 ID、attempt、原页码、文本哈希及精确的 `source_key=document_id:attempt`。
- 每次发布建立一个新的不可变集合，复用 SQLite 中已准备的向量，不重新运行模型。这样跨进程的 CLI 发布不会修改仍被旧请求使用的集合。代价是每次发布复制当前有效集合的向量，实际容量和延迟仍待任务 10.4 测量。
- 关键词快照是带校验和的 JSON，包含相同来源/尝试配对、原文映射、共享分词结果、词法版本及完整 embedding profile。目录中的指纹前缀用于缩短 Windows 路径；完整指纹和版本 UUID 仍参与校验。不会加载旧 pickle、manifest 或无指纹集合作为就绪依据。
- 文档库身份绑定 SQLite 位置与两个索引目录。配置目录或数据库位置变化会明确要求迁移/重建，不能把其他目录的同维度向量当作兼容库。只换生成模型不会改变这些资源身份。

## 发布顺序

1. 校验当前提交和候选的 profile、正文哈希、确定性片段 ID、原页码、完整片段数，以及向量数量/维度/有限数值。
2. 在独立版本集合暂存向量并读回验证，再于快照同目录暂存、fsync、原子替换 JSON。耗时构建期间不持有 SQLite 写锁，既有来源可查询，其他上传仍可登记。
3. 在短发布锁与 SQLite 事务中复核来源、attempt、删除 epoch/日志及旧指针，写入 `IndexCommit`、更新 `IndexPointer=current`，同时提交文档和任务的 ready 状态。
4. 切换进程中的轻量版本状态，回收没有读者的旧资源。内存不保存按请求复制的全库原文快照。

向量或快照失败时只清理该未发布版本，旧指针与先前有效来源保留。SQLite 提交后若内存切换异常，新读者会被阻止，必须从已提交指针恢复；不能把已提交文档改回 failed 或凭旧文件猜测回退。旧版本和孤立资源分别记录待处理/错误状态，`gc_pending/gc_error` 是两者的汇总；普通请求回收不能清除尚未成功处理的孤立资源错误。清理失败不会破坏已提交来源或掩盖有效检索结果，删除钩子会如实报告未完成。schema v3 幂等补齐 profile、根目录、库身份、校验和与退休标识；迁移在检查版本/缺列之前先取得 SQLite 写保留锁，使应用和 CLI 并发升级不会重复执行同一补列。旧无这些身份的提交不能直接采用。

## 启动与恢复

应用在启动 worker 前先恢复索引；取得单 worker 所有权后再次核对，再恢复非终态入库尝试。只读取 SQLite 的提交指针，不从文件夹、旧快照、manifest 或孤立 PDF 自动建立 ready 文档。

删除日志优先于 ready 行。进行中、失败或已完成的 tombstone 都不能被旧行覆盖；恢复旧库时若保留的已完成删除记录与 ready 行冲突，会重新标记待清理，而不是复活来源。相关请求失效，当前索引排除这些来源。此批负责索引和读者资源，原 PDF、历史摘录等完整删除仍由第 7 批接入，索引清理完成不会擅自标记整个删除成功。

关键词快照缺失、损坏或词法版本变化时，从仍有效的已提交 SQLite 片段重建，并验证对应 Chroma 向量；不调用 embedding 或生成服务。缺失/损坏的已提交向量会诚实阻止索引服务，不能由 manifest 冒充成功。未提交版本和本库可识别临时文件可回收；未知旧文件不会被导入。

同库 publisher 通过操作系统锁串行发布。外部进程的新提交可由下一次请求直接发现，无需重启应用或重建 agent。进程突然退出时由系统释放锁；提交前退出仍采用旧指针，提交后退出采用新指针。

## 请求视图、取消与回收

`open_view(document_ids, embedding_profile)` 固定已提交版本、去重范围、精确来源/尝试及删除 epoch。新文件发布不会扩大旧请求。向量在查询时按配对后的 `source_key` 过滤；关键词先限制范围再排名。过滤失败可以禁用向量路径，但不能用未过滤结果继续回答；词法排名也不能代替同空间证据分数。

请求先持有短期快照/集合租约；完成检索后只保留范围内选出的必要原文证据，不带全库映射或向量。跨进程租约由操作系统持有，退出自动释放；文件名含库身份，回收器只识别本库读者，共用索引目录的其他库不会阻止本库回收。

`assert_valid()` 每次复核持久状态，`guard_write(callback)` 将最终写回与来源复核放在同一 SQLite 写事务。`invalidate_source(id)` 要求先持久化删除，立即取消相关视图、清空证据别名，然后重建索引并报告索引部分是否清理完毕。若原生检索尚未返回，其租约保留到迟到结果被丢弃；未完成前不会误报资源已释放。无关范围仍可继续。

旧版本的 JSON 和 Chroma 集合只在短读者释放后回收，SQLite 仅保留必要提交身份。第 5 批将接入 API 的强制显式范围；第 6/7 批将把视图复核钩子接入完整历史和生成/SSE 取消合同。本批正常检索已使用已提交资源，不再回退旧的未版本化索引。

## 本地操作

按 [共用入库说明](document-ingestion.md) 准备模型缓存，然后运行：

```powershell
python -m scripts.simple_ingest --pdf-dir samples
```

默认等待发布终态；`ready=true` 后才具备索引查询条件。`--no-wait` 只保证任务已持久化。`--reset` 仍拒绝，已有库请先按 [迁移/备份说明](document-library-storage.md) 保存匹配的数据、原文件和删除日志，再重建或恢复。

无网络回归包含真实本地 Chroma 和提交前/后的进程退出测试；文本向量使用已标注替身，不把这些测试报告为真实本地模型质量或 GPU 性能通过。
