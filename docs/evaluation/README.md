# 双语条款问答核对集 v1（任务 1.6）

[bilingual-qa-v1.json](bilingual-qa-v1.json) 是供人工逐项评分的固定资料，绑定 task 1.5 的六份原 PDF 及清单 SHA-256；[检查报告](bilingual-qa-v1.check-report.json) 记录本次数据与实际原页锚点核对结果。资料由 Codex 阅读固定原文后编写，用户于 2026-10-26 至 2026-10-27 通过逐项卡片完成全部 54 项确认，`independent_human_review=completed`，详见[人工复核记录](bilingual-qa-v1.human-review.json)。其中一项中文问题经用户同意补充了“重疾给付何时结束”，使其与英文题等价；记录保留修订前后文本及题集哈希。此次是对展示资料和交互场景设计的复核，不是专业认证、实际模型输出评分或交互执行；真实模型及交互执行状态仍为 `not_run`。任务 1.6 完成资料准备，不代替 task 10.2、10.3 的实际验收。

## 组成与隔离

| 分区 | 数量 | 用途 |
| --- | ---: | --- |
| 验收正例 | 40 | 中问中、中问英、英问中、英问英各 10 个；每组覆盖医疗、重疾、寿险 |
| 验收负例 | 12 | 依据不足、离题、购买/配置建议、保证获赔各 3 个，包含中文和英文 |
| 校准问题 | 12 | 每份真实条款另取 2 个事实点，单独调试模型、检索与证据门槛 |
| 交互案例 | 10 | 逐份比较、五份局部缺据、同范围追问、范围切换、删除取消/历史清理/重启重传、比较上限、同名引用、上传不改选择 |

语言组合名称的左侧是问题语言，右侧是来源语言；默认答案跟随问题语言，引用始终保留来源原文。20 个验收事实点分别有等价中英文问题，形成四组各 10 个问题，便于对照跨语言表现；这不是 40 个互不相关的事实点。每个问题独立评分，不能拿某个语言版本的答案填另一组结果。

校准与验收分开存储为不同分区；校准事实 ID、语义标识、答案要点和证据定位均不复用验收事实。它们可以来自同一 PDF，甚至同页的不同条款，但不得只把验收题换一种说法放进校准集。自动检查能发现 ID、相同答案要点、相同锚点或相同问题的复用，不能证明所有语义改写都不存在泄漏；独立人工复核仍需核对事实目标。验收答案不得加入提示、关键词规则、阈值调试或示例缓存。先用校准集调参、固定模型/profile/阈值，再打开验收集；若据验收结果调参，应记录该套验收资料已被使用，并另建未使用的验收集。

`samples/` 两份合成 PDF、生成脚本及已有回归测试均保留。合成资料和无网络替身测试不计入这 40 个真实正例，也不代表真实本地模型、生成 API 已通过。

## 如何核对单题

先按 `document_ids` 将语料 ID 映射到本轮临时验收库的实际数据库 ID；语料 ID 不是可直接提交到生产 API 的整数文档 ID。映射必须核对原文件 SHA-256、版本及地区，不能只按文件名匹配。保留本次映射，重传/删除后不得复用旧 ID。

每题的 `fact_ids` 指向 `facts` 中的评分依据：

- `required_points` 是必须覆盖的语义要点；允许忠实的中英文转述，不按参考文字逐字匹配。
- `conditions` 是必须保留的适用范围、前置条件与例外；不能把“意外无等待期”扩大成所有疾病无等待期。
- `critical_fields` 记录金额/币种、日/月/年、比例、年龄、否定及条件的值、单位和限定语；与 `forbidden_claims` 一起检查关键错误。
- `evidence` 给出原 PDF 一基页码、定位锚点和该页提取文字哈希；事实同时绑定文件哈希和地区。先核对原页完整上下文，锚点本身不等于整条充分证据。

检查生成答案是否完整回答问题、保留必要条件并使用正确语言，再逐一打开引用核对来源、页码、原文与编号。译文不能冒充原文，引用必须在当前范围内、属于本轮仍有效来源；高 BM25/RRF 分数、Recall@5 或引用了相似标题都不算事实正确。

负例的 `review_evidence` 是评分人检查“缺少个人保单信息”等边界的原文定位，不是允许公开输出的引用。依据不足案例针对未提供个人保额、保费或生效日的公开产品条款，不断言整份 PDF 没有相关概念。所有拒答/建议边界公开引用均须为空，不从其他文档补答案。

## 评分规则

正例只有在完整、事实正确、必要条件完整、来源/页码/引用归属正确、范围正确、语言正确且完成正常终态时记为一次成功。仅检索命中、展示片段、缺据拒答、部分回答或服务不可用都不是完整回答成功。四组各至少 9/10；一组 10/10 不能抵扣另一组 8/10。

任何已输出答案中的关键金额、期限、否定、适用条件或引用归属错误，以及任何范围外证据，均使整体验收失败，即使四组已各达到 9 次成功。允许的未成功可以是不编造事实的拒答/局部结果，不能是关键事实错误。遗漏了会改变意思的条件按关键错误处理，不能只打“部分回答”绕过否决。

至少 12 个负例必须全部正确，且边界引用为空。购买/配置和保证获赔使用资料中的 `advice` 语义标签；离题和缺据用 `refusal`。这些是题集标签，后续执行适配器需与实际 API 的终态字段显式映射，不修改期望来适应错误实现。

交互案例单独评分，两种传输均执行，不能由 40 个独立正例代替。比较必须逐份有依据或列明缺据；局部缺据场景明确注入受控检索不足，不能把它当作原 PDF 缺少该条款。删除、故障、同名导入等仅在隔离临时库操作，不删除 `data/acceptance/official-v1` 的核验原件。交互中的 `steps`、`required_checks` 全部满足才通过，尚未执行时维持 `not_run`。

```powershell
# 结构、四组数量、来源身份、页码、注释完整性和分区隔离；默认不联网。
python -m scripts.check_qa_dataset

# 进一步逐页调用现有项目提取入口，验证实际 PDF 哈希和全部标注锚点。
python -m scripts.check_qa_dataset --pdf-dir data/acceptance/official-v1 --report data/acceptance/qa-dataset-check.json
```

## 人工评分记录与规则核算

每题保存原始问题、实际范围/ID 映射、最终答案及终态、引用、所用模型/profile、传输方式、耗时和调用记录。然后在独立 JSON 数组中为每个正例和负例填写一行，不把预期答案作为实际结果。必填格式如下（此例只是格式，不能作为真实已通过记录）：

```json
[
  {
    "case_id": "acc.zh.medical.waiting.zh",
    "outcome": "partial",
    "required_points_correct": false,
    "conditions_preserved": true,
    "answer_language_correct": true,
    "scope_correct": true,
    "citation_status": "missing",
    "critical_errors": []
  }
]
```

`outcome` 可为 `complete/partial/refusal/advice/unavailable/retrieval_only`；`citation_status` 可为 `correct/empty/missing/wrong/out_of_scope`。布尔判断必须明确填写；错误列表记录如 `wrong_amount`、`wrong_deadline`、`lost_negation`、`wrong_condition`、`wrong_provenance`，不得以缺省值当作已检查。`conditions_preserved=false`、范围错误、引用错误或非空关键错误列表均触发否决。

```powershell
python -m scripts.check_qa_dataset --reviews path/to/manual-reviews.json --report data/acceptance/manual-rubric.json
```

规则核算拒绝重复或未知题号，缺题不通过；一次报告只用同一模型/profile及一种传输的 52 道验收题，不累计多次运行的成功数。`rubric_pass` 只是对人工判断的算术核算，`actual_runtime_verified` 始终为 `false`，不据此宣称真实模型/API可用。交互、实际服务证据及完整运行报告仍须另行审核。

实际验收记录至少包含：本地 embedding 模型 ID、固定 revision、tokenizer/预处理指纹、距离与阈值、生成模型、实际设备与批大小、加载/入库耗时、内存/显存峰值、首字与完成时延、生成调用量、每组成功数与所有错误、负例结果和交互记录。不得记录 API Key。缺真实本地权重或真实生成 API 时保留未完成，不能以替身评分、规则核算通过或数据检查通过替代真实联合验收。
