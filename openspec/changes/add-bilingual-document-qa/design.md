# Design

## Context

动机与范围见 `proposal.md`，行为合同见三份现有 delta specs；术语与已确认取舍以根目录 `CONTEXT.md` 和已生效的 `docs/adr/0002`、`0003`、`0004` 为依据，`0001` 已被 `0004` 取代。本设计恢复本地 embedding 与生成 API 的数据边界，撤回由错误 Q5 推导的双 API 部署决定；显式范围、选择、追问与删除合同保持不变。

已核实的现状：
- `simple_ingest.py` 单独提取 PDF，按文件名派生片段 ID，写 Chroma、BM25 与 manifest，但不使用已有 SQLite 文档身份，并硬编码样本产品与日期。
- BM25 只在启动时从硬编码目录加载，corpus 可凭磁盘文件回退列举；上传、删除与动态一致发布尚未建立。
- ask 的模型无显式范围、方式或回答语言；batch 自行构造无范围 QueryRequest，示例及 smoke 脚本也依赖旧合同。
- 向量与 BM25 在全库各取候选再融合，统一 top-k 无法保证逐文档比较覆盖；过滤错误可能退回未过滤结果，refetch 顺序不应假设等于融合顺序。
- 距离、相似度与 BM25/RRF 混取最大值，中文关键词边界与提示词偏置会误拒英文；生成分支与 SSE 分支重复。
- 历史保存完整 retrieved_chunks；前文只按 session 查询，未按文档范围隔离，默认重写关闭，不能据“有历史”宣称已支持可靠追问。
- 远程 embedding 已有接口封装，但与生成共用地址和凭据；现有启动脚本强制中文模型/阈值，正常依赖含本地 HF 路径。
- 当前检出项目默认 data 路径只有占位文件，无已有个人库或旧索引；有两份合成样本可首次导入。不能据此推断其他目录没有旧数据。

## Goals / Non-Goals

**Goals:**
- 保留 FastAPI、SQLite、Chroma、BM25 与现有引用查看器，建立共用入库、查询准备、索引协调和删除服务。
- 用显式范围、会话范围 epoch、逐文档覆盖和删除失效规则控制证据生命周期。
- 让可恢复发布、取消、清理和真实本地模型/生成 API 联合验收具有明确完成条件。
- 按 50 份文档设计与实测，超过提示后仍可上传；每份最多 200 页，每次比较最多 5 份。

**Non-Goals:**
- 不部署本地生成大模型，不将正文发送到远程 embedding 服务，不引入 OCR、分布式 worker、SQL/KG 旁路、整份 PDF 生成上传或全文翻译索引。
- 不提供文档原位替换/版本编辑；同名不同内容是不同文档，删除后的重传是新身份。
- 不预先承诺未实测的 API 时限；繁体文档不纳入首批真实验收，不把它扩大成已验证能力。
- 不在本次规划同步中收集实际语料、调用付费模型或实施代码。

## Decisions

### 1. 本地多语言 embedding，生成独立使用 API

复用现有 HuggingFaceEmbeddings / SentenceTransformers 的本地 Python 路径，模型在应用进程内推理，不要求另起 HTTP 服务或训练模型。BGE-M3 的 dense embedding 是首选评测候选，不因模型名称或标称多语言能力直接认定通过验收；具体模型由真实语料质量与资源测试确定。

生成独立配置 `GENERATION_API_BASE_URL`、`GENERATION_API_KEY`、`GENERATION_MODEL`；可保留旧 OPENAI_* 的显式兼容别名并说明优先级。本地 embedding 单独配置模型 ID/固定 revision、缓存目录、device 与 batch size，不配置远程 embedding 地址或凭据。模型缺失或加载失败时明确标记入库/语义检索不可用，不能偷用生成服务或 hash 模型。

允许首次下载公开模型权重及配套 tokenizer 并缓存，记录实际 revision；后续加载缓存并在本地向量化。缓存完整时不依赖模型下载站点可访问，不在每次启动强制联网；缺少缓存且下载不可用时给出准备步骤与诚实未就绪状态。模型下载不携带保单正文或用户问题，文档解析、切块、向量化与检索全部在本机；只有生成 API 接收本轮问题、理解追问必需的同范围前文及必要证据，不发送整份 PDF。

优先使用可用 GPU；发生显存不足时有界地降低批大小重试，仍无法运行则释放对应模型资源并尝试同模型 CPU 路径。无可用 GPU 时直接使用 CPU，并向用户显示实际设备及速度可能变慢的提示。CPU/GPU 共用模型 revision、预处理、前缀及归一化配置，不静默换 hash、其他模型或远程服务；全部路径失败则明确不可用，不无限重试。设备变化本身不创建另一语义空间，但需验证向量数值有效及同 profile 跨设备检索一致性容差。

本地推理在线程或受控执行器中运行，限制并发，验证输出数量、维度与有限数值；取消后迟到结果不得发布。完整运行依赖 HF/SentenceTransformers、torch 及缓存模型，交付 CPU/GPU 安装路径；轻量 Docker 仅完成应用存活时不得宣称完整双语问答就绪。无网络 CI 通过注入替身验证合同，真实模型质量和硬件表现由独立验收确认。

### 2. SQLite 统一文档身份、处理与删除事实

沿用稳定整数 Document.id，文件按受控内部身份存储，原名仅展示。扩展处理阶段、语言、错误页码/原因、尝试版本、已发布指纹和删除状态；片段保存原文、原页码、章节/页内顺序、文本哈希和向量 ID，不伪造产品或日期。

增加索引版本/提交指针、会话范围 epoch 与持久删除任务记录。已有 status=active 不等于 processing_status=ready；删除后只留必要身份 tombstone，不能留原文、可读取路径或派生资料。同内容活跃/ready 重传去重；failed 可增加尝试重跑；deleted 内容重新上传分配新 ID，防止旧引用自动复活。

使用版本化、幂等 SQLite 迁移，create_all 仅负责新表，不能代替补列；旧历史无范围时标未知且不能加入新追问。manifest 仅作可选导出/导入输入，不能覆盖数据库 readiness 或删除 tombstone。

### 3. API 合同与不兼容范围变更

| 接口 | 设计合同 |
| --- | --- |
| POST /api/v1/documents | 每请求一份 multipart PDF；新任务 202，已有活跃/ready 同内容返回 200，前端可多选逐份提交 |
| GET /api/v1/documents 与 /{id} | 文档身份、名称、页数、语言、阶段、失败页与删除进度；不伪造百分比 |
| GET /api/v1/documents/{id}/file | 按 ID 返回受控原文件；deleting/deleted 不再提供内容，已删除来源返回明确失效信息 |
| DELETE /api/v1/documents/{id} | 幂等发起删除并返回 202/已完成状态；清理未完成不能显示成功 |
| GET /api/v1/corpus | 文档库的主要字段兼容投影；无磁盘即就绪回退 |
| POST /api/v1/queries/ask | 必填非空 document_ids；answer_language=auto/zh/en；query_mode=auto/qa/compare；保留 stream 等既有参数 |
| POST /api/v1/queries/batch | 结构化请求含 questions 与必填共同 document_ids、语言及方式参数，不再内部构造无范围请求 |

省略、null、空范围、未知/非 ready/deleting/deleted ID 返回 422；批量共同范围在执行任何子问题前校验，子问题再按方式检查比较上限。比较已解析且超过 5 份时也在 SSE 打开前返回 422，不截取前 5；普通问答可以选择更多文档。

保留 question、answer、answer_kind、retrieved_chunks 等主要响应字段，补充实际 document_ids、answer_language、query_mode 和会话 epoch。澄清用明确的 clarification 终态；比较每文档的事实或缺据状态具有可展示身份。来源失效的历史引用仅保留 ID/名称/页码与 source_status=deleted，无 content、向量或原文链接。

非 PDF 类型 415、超出文件大小 413；200 页为硬限制，超过整份失败。20 MiB 仍作为公开且可配置的文件大小初值，非本轮用户指定目标。50 份是设计/验收规模，超过显示提示但不拒绝上传，删除 tombstone 不算仍保存的文档。

### 4. 共用完整性检查与后台入库

新增 DocumentIngestionService，由网页与 CLI 共同调用。有效 PDF、加密/损坏、页数检查、PyMuPDF 逐页提取、明显乱码与疑似扫描检查在线程中执行。空白页可以跳过且不改变原页码；有扫描内容或无法可靠读取的非空页则整份 failed，并给出页码，不发布部分资料。存在标志图不等于扫描，不用图片存在与否替代正文质量判断，也不承诺无需 OCR 就能准确理解任意图表。

保留原文与检索规范化副本。按页、条款编号、章节和段落切分，再用本地 embedding tokenizer 的输入预算限制长块并重叠，同时为生成 API 保留安全上下文预算；tokenizer、截断与重叠策略写入 profile，不能依靠模型静默截断丢失条件。必要条件、否定与标题随相邻块保存，原始页码稳定。chunk ID 由文档 ID、尝试、页码、顺序与内容哈希派生。

使用单 worker、有界内存队列和 SQLite 持久任务来源；队列满不丢任务。重启重排非终态任务，重跑只清理对应尝试，不执行目录级 reset。本地 embedding 在线程或受控执行器中分批运行，结果验证和片段检查点使重试幂等；失败原因区分模型不可用与文档没有可读依据。

### 5. 索引一致发布，避免长期持有全库原文快照

IndexCoordinator 管理配置目录、不可变索引版本、短发布锁和已提交指针：
1. 候选片段/向量写入暂存身份，尚未 ready，不属于任何新请求的可见文档。
2. 生成 ready 文档加候选的 BM25/片段映射快照；版本化文件在同目录完成原子落盘。
3. 短锁内验证完整性，以 SQLite 事务提交 ready、版本与指针，替换内存资源；提交后切换异常先阻止新查询并按指针恢复。
4. 启动只加载已提交版本，并优先重放删除状态；缺失 BM25 从仍有效片段重建，不能从旧 manifest 复活已删除来源。

请求冻结范围和发布版本，检索阶段短暂使用版本资源，生成阶段只持有范围内已选证据，不长期把完整文档库原文快照挂在每个请求上。这既保证新增文件不扩张当前范围，也使删除可以释放对应读者并清理含原文的旧版本；不承诺任意旧全库版本永久可读。

新增发布失败保留原有效库；删除期间该来源先失效，其他来源继续服务。旧快照、临时文件及源文本缓存有文档身份索引，删除时可定位清除/重建；不能只把新索引排除 A，却永久保留含 A 原文的旧快照。文件路径统一遵守配置，不再使用启动硬编码目录。

### 6. 显式范围与两个检索方式

QueryService 在任何答案流前完成范围、语言、方式和会话准备，捕获去重 IDs、允许的文档/尝试对与取消令牌。向量查询按确切 (document_id, published_attempt) 过滤，不能用两个独立集合的交叉组合放入旧尝试；BM25 先限制允许候选再取 top-k，零词项匹配不贡献排名。过滤失败禁用路径或降级，不做无范围重试；可选改写不能替换 IDs，SQL/KG 旁路不启用。

普通 qa 在所选集合内按相关性检索，不要求逐份覆盖。compare 对最多 5 份分别执行召回、证据门槛和覆盖记录，复用本轮问题向量以减少重复本地向量化；按文档分配证据预算，不能让一份占满 top-k。每份输出有证据事实或“未找到充分依据”，其中一份缺据不阻止回答其他份；若整体证据超出可安全生成的上下文预算，则要求缩小问题/范围，不伪装为完成全部比较。

RRF 只排序，refetch 按请求 ID 顺序恢复；最终再次校验来源、尝试与取消状态。同页不同有效条款按 chunk/原文去重，不以同名+页码去掉必要证据。固定最终证据序列后生成全局引用编号，公开引用不得再重排导致编号错位。

### 7. 可见意图识别与同范围追问

手动 query_mode 优先；auto 对明确比较表达识别为 compare，普通解释为 qa，无法确定时返回 clarification。界面显示实际方式并提供修改。当前问题独立且模式明确时不强制多一次改写 API；确需消解追问或判断意图时复用小型结构化准备调用，限制输入，失败不得猜测范围、产品或比较方式。

会话状态按 session_id、排序去重后的 scope fingerprint 与递增 epoch 管理。相同范围可读取当前 epoch 的必要前文；更改选择创建新 epoch，改回旧集合也不复活旧上下文。新文档上传不会改变 scope；迟到的旧回答只能归入原 epoch，不能进入新范围前文。来源删除失效相关会话 epoch。

历史是存档，前文是本轮理解材料：改写只消解指代，仍保留原问题、产品、金额、日期、单位和否定。每轮必须在当前有效范围重新检索与引用，不从旧助理答案推断新事实。指代不能唯一消解时澄清。请求快照允许用户切换选择时旧请求继续，但删除是取消该请求的显式例外。

### 8. 删除是可恢复的清理流程

DocumentDeletionService 与入库、查询共享生命周期协调器：
1. 在短锁中持久标记 deleting、递增失效 epoch、注册不可见 tombstone，移出选择，取消所有范围包含该 ID 的预处理、生成/SSE 与入库任务；停止上游流并释放对应证据读者。
2. 所有迟到的向量写入、ready 发布、token/end 事件和历史保存都复核取消/删除版本。不能让删除前启动的任务在清理后重新写回原文。
3. 清理受控原 PDF、提取正文与片段、Chroma 向量、BM25 和映射中的来源，重建仍有效文档索引；清除系统管理旧快照、临时件与原文缓存。删除不依赖重新向量化、模型加载或新的生成 API 调用。
4. 历史引用按源 ID 清除 content 与其他原文载荷，仅留必要身份、页码和 deleted 标记；清除相关前文/改写缓存中的来源资料。已有答案正文保留，即使它包含此前引用的文字/数值，也不再作为后续事实依据。
5. 完成可读源副本清理与新索引发布后标记 deleted。清理失败显示未完成及原因，来源仍不可查询；重启优先继续持久删除任务，不回滚为 ready。

对正在 A+B 比较的删除，整条相关回答取消，不偷换成只答 B；无关来源的请求可继续。已删除 ID 永久失效，重传相同内容是新 ID。应用自管快照受删除规则约束，用户另行持有的备份不自动遍历删除；恢复/回退必须重放保留下来的删除日志，避免自动复活来源。此处不是对外部 API 留存策略的删除承诺。

### 9. 双语证据、评分与运行状态

LanguageService 统一显式参数、问题语言指令、主要语言、中文回退；入库与查询共用中文分词、Unicode/大小写规范化和英文词项规则。术语映射帮助召回，不抹除地区、产品、限制或否定差异，不把相关词映射当作事实等价。

本地 embedding 指纹包含实际模型 ID/固定 revision、tokenizer、维度、归一化、前缀、距离、文本处理和切块版本，不含凭据。换模型即便同维度也重建新 collection；只换生成模型不强制重建向量，但完整回答需重新验证。明确设 cosine，保存 raw_distance，门槛相关性采用 clamp(1-distance,0,1)；关键词与 RRF 仅排名，BM25 独有候选需取得同空间证据分数，不能用 BM25 原始高分放行。

双语拒答由原因码和本地模板呈现，合法短英文问题不再受中文词表硬门槛。真实证据不足与 本地 embedding 模型不可用必须区分；生成不可用可保留有效片段和诚实说明。生成提示使用已解析语言、固定三段标题和编号证据，将文档视作资料而非指令。保留 answer 文本协议，前端识别受控中英标题。

健康接口区分应用存活、文档索引、本地 embedding 模型/缓存就绪及实际设备、生成 API 配置/可用性，不把依赖缺失一律报正常。Docker 存活检查不触发模型下载或付费 API 调用，无模型或凭据时不宣称完整问答可用。流中断、超时和删除取消均给出诚实终态；正式引用仍在最终事件更新。

### 10. 前端保持双栏并显式管理状态

增加上传、多选文档、当前范围、回答语言、自动/普通/比较方式、删除入口和阶段/错误提示。新 ready 文档只提示可选，不自动追加、替换或全选；首次无保存选择保持空，刷新只恢复仍有效的已保存选择。

查询选择与 pdfSelect 分开，后者只切换当前答案引用原文。默认启用流式，提交时复制 IDs、方式和语言；选择变化更新会话 epoch，不修改进行中旧范围。删除在 UI 确认具体文件后发起，显示取消/清理进度，成功后旧引用显示来源已删除且无摘录；文件名与错误文本均转义。完整 UI 国际化不在首期范围。

### 11. 真实语料、本地模型与生成 API 联合验收

合成样本继续做稳定、无网络 CI。首批通过受控清单从保险公司官网采集 6 份可读 PDF：简体中文 3 份、英文 3 份，各语言覆盖医疗、重疾、寿险；无繁体候选。清单记录官方 URL、发行者、地区、产品/类别、正文可见版本、采集时间、页数与文件哈希。选择与版本固定，跨地区结果分开归属；质量检查不通过则记录原因并替换，不能弱化完整性规则。当前只已核查若干来源可访问，不声称六份正式语料已采集或通过项目解析。

人工标注金额、期限、除外/否定条件及原页码。校准集与验收集分开，真实验收合同：
- 40 个明确可回答问题，四种组合各 10 个，每组至少 9 个完整正确且有原文引用。
- 任一输出关键金额/期限/否定/适用条件或引用归属错误，整体不通过；正例允许的未通过不能是关键事实错误。
- 至少 12 个证据不足、离题、购买建议与保证获赔负例全部正确；范围外证据/引用为零。
- 比较覆盖与缺据、追问/范围切换、删除取消/清理另设交互验收，不以 40 个独立问题替代。
- Recall@5 等仅作检索诊断，不再保留旧 80% 召回发布门槛；完整回答才是正例成功。

独立评测使用真实本地 embedding 模型与实际生成 API，记录模型 revision、设备、批大小、加载/内存与显存峰值、生成调用量、入库时长、普通/最多五文档比较首字与完成时延、错误类型；以 50 文档库及 200 页边界验证容量，超过规模提示。等待时间目标在接入后根据实测记录确定，本轮不设未验证秒数。缺少可用本地权重或真实生成 API 配置时，实际验收保持未完成，不能用替身、仅检索或缺密钥降级冒充可用版本。

## Risks / Trade-offs

- [生成 API 的配额、成本与网络不确定] -> 独立配置与诊断、有界退避、最小必要证据，实测再定等待目标。
- [本地模型下载、内存与显存不足] -> 首次下载并缓存固定版本，GPU 优先并缩小批次，必要时同模型 CPU 回退且提示速度；具体可用性以实测为准。
- [逐份比较增加检索与上下文开销] -> 硬上限 5 份、逐份预算与缺据标识，不能静默截断覆盖。
- [扫描/乱码检测不完美] -> 保守整份失败并定位页，区分空白/装饰图，不承诺无 OCR 理解任意图表。
- [数据库、Chroma 和文件无跨系统事务] -> 提交指针、尝试/删除 epoch、短锁和故障恢复验证；删除未完成不能报成功。
- [旧快照或迟到写入复活原文] -> 不长期持有全库原文、清理所有应用管理副本、取消与最终写入复核、启动先重放删除日志。
- [保留答案正文仍可能包含旧来源内容] -> 按已确认边界保留并标记失效，清除引用摘录，不把旧答案用于新事实。
- [跨地区术语和产品条件差异] -> 清单记录地区/产品/版本，比较逐份归属，不用语言翻译推断制度等价。
- [50 文档以上未做首期性能保证] -> 提示并允许继续使用，报告实测规模，不误设总数硬上限。

## Migration Plan

1. 主路径按当前空 data 初始化并通过共用 CLI 导入样本。对实际已有库先备份，运行幂等 schema 迁移；旧 active 不直接变 ready，旧历史无范围不用于新上下文。
2. 准备并缓存本地模型、配置生成 API，先完成本地加载/设备回退、生成连通性、维度/输入限制与小规模校准；不复用无指纹的旧中文/hash 向量。若有旧源文件，通过共用入口重建并保留身份映射，缺原文件明确报错。
3. 同步升级 ask、batch、页面、README 示例及 smoke/空库检查：必填显式范围，缺省/null/空返回 422；旧 API 默认全库是有意移除的合同。
4. 运行 6 份真实语料、本地模型与生成 API 的完整联合验收，记录容量/时延，更新最终 profile 与等待目标后开放正常使用。
5. 回退前停止工作、保存新增源文件及删除日志，再恢复匹配的应用/schema/索引。恢复后先重放删除 tombstone 和清理，禁止恢复已删除来源；不通过丢弃新文档实现回退。

## Open Questions

- 具体生成服务、本地 embedding 模型 ID/revision、批大小与输入 token 限制，在实际联合验证阶段确定，不改变本地向量化与生成 API 的边界。
- 以本地真实模型及生成 API 测量入库和首字/完成时间，并记录 CPU/GPU 表现后确定等待目标；当前没有未解决的产品范围决策。
